# 设计笔记 TG-N01：登录页密码显示/隐藏

## 目标

为 `/login` 增加可访问的密码显示/隐藏控件，同时保持现有原生表单、认证流程、失败重渲染和注册页行为不变。

## 方案

- `src/login-page.js` 继续负责服务端渲染，密码输入保持 `type="password"`，并增加 `type="button"` 的切换按钮。
- 按钮通过 `aria-controls="login-password"` 关联密码框，使用 `aria-pressed` 和按钮文字表达当前状态。
- 在登录表单末尾以内联一个很小的渐进增强脚本。脚本只查询当前页面的登录控件，监听按钮点击和 Enter/Space 键盘激活；切换后恢复按钮焦点。
- 不使用表单提交、URL 操作、认证服务、Cookie、本地存储或日志。服务端失败重渲染天然重新生成隐藏状态，并继续不回填输入值。
- 无 JavaScript 时按钮是无副作用的普通按钮，原密码输入框和原提交按钮仍由浏览器原生表单提交支持。

## 关键决策

1. 使用 `aria-pressed` 而不是改变按钮角色，保留原生按钮的 Tab、Enter、Space 语义。
2. 脚本绑定在登录页内容中而非全局布局，避免影响注册页和其他页面。
3. 页面每次服务端渲染都固定输出密码隐藏状态，确保新导航和失败响应不泄露密码。
