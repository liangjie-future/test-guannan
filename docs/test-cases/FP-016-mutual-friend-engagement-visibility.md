# 测试场景 FP-016：好友帖子的点赞评论共同好友可见性

对应验收标准（好友帖子上的点赞 / 评论仅共同好友可见）与边界 / 错误路径。
测试文件：`tests/test_engagement.py`，运行 `python3 -m pytest -q`。

种子约定：V=alice(id=1，查看者)、A=bob(id=2，帖子作者)、C=carol(id=3，V 与 A
的共同好友)、D=dave(id=4，仅 A 的好友)、E=erin(id=5，陌生人)；关注边
`1→2、1→3、2→3、2→4`（F(V)={A,C}，F(A)={C,D}，共同好友(V,A)={C}，W(V,A)={V,A,C}）。
A 的帖子 P 上按场景撒点赞 / 评论（显式时间戳直插 SQLite 保证时序确定）。
变体种子按 TC 裁剪关注边 / 帖子 / 互动。

## TC-01 点赞写入：成功与幂等

- **步骤**：`like(V, P)` → 再次 `like(V, P)`。
- **期望**：首次 `{status: OK, created: True}`；重复 `{status: OK, created: False}`；
  存储恰一条点赞行（不重复）；给自己帖子点赞允许（OK）。

## TC-02 评论写入：成功与内容规则

- **步骤**：`comment(C, P, "nice post")`；变体内容：空白文本、281 字、恰 280 字、非字符串。
- **期望**：成功 `{status: OK, comment: {id, post_id, user_id, content, created_at}}`；
  全空白 → `EMPTY_CONTENT`；281 字 → `TOO_LONG`；恰 280 字（含边界）→ OK；
  `content` 非字符串抛 `TypeError`（对齐 FP-013）；失败不产生评论行。

## TC-03 写入错误路径与校验顺序

- **步骤**：`like` / `comment` 传入不存在的用户 id、不存在的帖子 id、以及
  「用户不存在 + 内容为空」组合。
- **期望**：分别 `{status: ERROR, reason: USER_NOT_FOUND}` / `POST_NOT_FOUND`；
  校验顺序 用户存在 → 帖子存在 → 内容规则（组合场景返回 `USER_NOT_FOUND`）；
  任何失败路径不写入 likes / comments 行。

## TC-04 可见性核心（验收主场景）

- **前置**：完整种子；P 上有 C / D / E 三人的点赞与评论。
- **步骤**：`getVisibleEngagement(V, P)`。
- **期望**：仅 C 的点赞与评论可见（共同好友）；D（仅帖主好友）与 E（陌生人）
  的点赞与评论完全不可见；可见条目携带 `username` 且与存储一致。

## TC-05 自己与帖主例外（设计口径）

- **前置**：P 上另有 V 与 A 各自的点赞 / 评论。
- **期望**：V 的查询结果含 V 自己的点赞 / 评论（自己始终可见）与 A（帖主）
  的点赞 / 评论；两者与共同好友 C 一并呈现。

## TC-06 空态与查询坍缩（边界）

- **期望**：帖子无任何互动 → `{"post_id", "likes": [], "comments": []}`；
  帖子不存在 → 两组皆空、不抛错；查看者 id 不存在 → 不崩溃（自然坍缩：
  W={缺失 id, 作者}，仅作者自身互动可见）。

## TC-07 帖主查看自己的帖子

- **步骤**：`getVisibleEngagement(A, P)`（W(A,A)={A}∪F(A)={A,C,D}）。
- **期望**：C 与 D 的互动可见；E（帖主也不认识的人）不可见。

## TC-08 非好友帖子统一规则（边界）

- **前置**：变体种子新增作者 X（V 未关注 X），X 的帖子上有 C / D / E 的互动，
  X 关注 C（X 与 V 的共同好友 = {C}）。
- **期望**：规则统一适用不特判——C 的互动对 V 可见，D / E 不可见，
  另见 V 自己与 X 的互动可见。

## TC-09 关注图变化即时反映（FP-011 联调面）

- **期望**：变体种子去掉 V→C 边（重建）→ C 的互动对 V 不可见；
  完整种子上 `addFollow(V, D)` 后 → D 的互动立即可见（无取关原语，
  反向场景以变体种子验证）。

## TC-10 排序：时间瞬间升序与并列稳定

- **前置**：可见评论 / 点赞时间交错，含 `+02:00` 偏移（字典序会排错位）。
- **期望**：可见点赞 / 评论各按 `created_at` 真实瞬间升序；同时刻并列均出现、
  不抛错（次序不限定）；过滤后次序仍保持升序。

## TC-11 存储原语与持久化（FP-001 扩展）

- **期望**：`getPostById` 命中返回帖子字段、未命中返回 `None`；`addLike`
  幂等（两次一行）；`getLikesByPostId` / `getCommentsByPostId` 返回该帖全部
  互动（不混入他帖）；关闭重开（等价重启）后点赞 / 评论仍可读回。

## TC-12 内存契约替身路径（§6 Mock）

- 用最小契约替身（users / posts / follows / likes / comments 内存模拟，仅实现
  消费的方法）重放 TC-04 核心断言：共同好友可见、单方好友与陌生人不可见；
  行为者缺失时 `username` 为 `None` 不崩溃；返回条目为副本——修改返回对象
  不影响后续查询结果。

## 运行

```bash
python3 -m pytest -q        # 全部 Python 测试（含 FP-001 / FP-011 / FP-013 / FP-015）
npm test                    # Node 端回归
```
